# Структуры данных и алгоритмы

## Состояние игры и история

- Настройки текущей игры (`length`, `base` и `secret`) передаются как объект `gameOptions`. Этот объект создаётся при запуске игры и передаётся в игровое поле; отдельного класса или хранилища для состояния активной игры нет.
- Результат проверки попытки хранится в объекте `bullsAndCows` с полями `bulls` и `cows`.
- История попыток — массив объектов `historyType`: каждая запись содержит введённую строку `guess` и объект `result`. Запись добавляется в конец массива, поэтому сохраняется порядок ходов. Массив удобен для последовательного отображения истории и определения числа ходов по `history.length`. Повтор одной и той же попытки не добавляется.
- Общие данные игры находятся в объекте `gameStorage`: `history` хранит попытки текущей игры, а `wins` — результаты побед. История сбрасывается при начале новой игры. Победы сериализуются в JSON и сохраняются в `localStorage`, поэтому остаются доступны после перезагрузки страницы.

## Оценка попытки

Функция `evaluateSecret`. Она принимает секрет и попытку, проходит по символам попытки и для каждого символа:

1. Если символ совпадает с символом секрета на той же позиции, увеличивает число быков.
2. Иначе, если этот символ есть в секрете, увеличивает число коров.

Сравнение символов попытки выполняется в нижнем регистре. Валидатор до оценки проверяет длину, допустимость символов и отсутствие повторов; поэтому проверка присутствия символа в секрете не требует учитывать кратность. Функция возвращает объект `{ bulls, cows }`. Для строки длины `n` текущая реализация выполняет поиск символа в секрете для каждой позиции, что даёт сложность O(n^2) и дополнительную память O(1), не считая создаваемого массива символов.

## Подсчёт возможных секретов

`countPossibleSecrets(length, base)` считает количество строк длины `length`, составленных из `base` символов без повторений. Для некорректных значений (`length < 0`, `base < 0` или `length > base`) функция возвращает `0`. Базовый случай `length === 0` даёт `1` — существует одна пустая последовательность.

Рекуррентное вычисление:
На первой позиции есть `base` вариантов; после выбора одного символа остаётся на один символ меньше для следующих позиций. Таким образом, результат равен числу размещений без повторений.

Результаты рекурсии кэшируются в `Map`, где ключ — пара `length` и `base`. Это позволяет переиспользовать ранее вычисленные подзадачи. После заполнения кэша вызов для той же пары выполняется за O(1); первый вызов имеет глубину рекурсии O(length) и вычисляет O(length) подзадач.

## Сложность

Обозначим через `n` длину секрета или попытки, через `b` — основание системы счисления.

- `generateSecret`: одна проверка уникальности использует `includes`, которая просматривает уже собранную строку за O(n). В игре `base` и `length` ограничены небольшими значениями, поэтому при завершении генерации стоимость практически ограничена константой.
- `evaluateSecret` (оценка попытки): O(n^2) времени, потому что для каждой позиции при необходимости вызывается `guess.includes`, выполняющий линейный поиск; O(n) дополнительной памяти на массив символов, создаваемый spread-оператором и `map`.
- `isValidGuess`: ожидаемое O(n) времени и O(n) памяти. Создание `Set` для проверки повторов и проход по символам для проверки допустимости линейны по длине строки.
- `countPossibleSecrets`: O(length) времени и O(length) памяти стека при первом вызове без готового результата в кэше: рекурсия делает один вызов на каждый следующий уровень. Повторный вызов для уже закэшированной пары `(length, base)` занимает O(1) времени.

## Принципы чистого кода

- **Разделение ответственности.** В [src/core/generateSecret.ts](src/core/generateSecret.ts) `generateSecret` создаёт секрет, [src/core/evaluateSecret.ts](src/core/evaluateSecret.ts) `evaluateSecret` подсчитывает быков и коров, а [src/core/isValidGuess.ts](src/core/isValidGuess.ts) `isValidGuess` проверяет попытку. [src/ui/sections/gameFieldset.ts](src/ui/sections/gameFieldset.ts) связывает эти операции с полями и событиями интерфейса, не дублируя их основную логику.
- **Переиспользование вместо дублирования (DRY).** [src/core/createDigitValidator.ts](src/core/createDigitValidator.ts) `createDigitValidator` централизует проверку символа в заданном основании. Её используют и `isValidGuess`, и `createGameFieldset` при обработке ввода.
- **Ранний возврат для ошибочных условий.** `generateSecret` сразу возвращает `undefined` для неподдерживаемой длины или основания. `isValidGuess` сразу возвращает `false`, если длина неверна или в попытке есть повторы. Проверки условий находятся рядом с входом в функцию и не усложняют основной путь.
- **Явные имена и типы предметной области.** Названия `countPossibleSecrets`, `historyType` и `bullsAndCows` сообщают назначение функций и данных. В [src/type/types.ts](src/type/types.ts) типы `bullsAndCows`, `gameOptions`, `historyType` и `winsType` задают форму результатов, настроек игры, попыток и побед.
- **Управляемые зависимости для проверяемости.** `generateSecret` принимает функцию `random` с `Math.random` по умолчанию. Это позволяет подставить контролируемый источник случайных чисел в тестах вместо зависимости от непредсказуемого поведения генератора.
